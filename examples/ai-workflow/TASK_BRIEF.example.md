# TASK_BRIEF Example

## タスク概要

- タスク名: 問い合わせ一覧に担当者フィルタを追加する
- 種別: `feat`
- 目的: 担当者ごとの未処理問い合わせを素早く確認できるようにする
- 背景: リーダーが担当者別の滞留状況を手動で確認している
- 期限: 2026-04-10
- 担当: AI 実装 + 人間レビュー

## 対象範囲

- 変更するファイル: `apps/web/src/pages/inquiries/*`, `apps/api/app/controllers/inquiries_controller.rb`
- 変更しないファイル: 認証、通知、監査ログ形式
- 関連する設計資料: `design/03-details/flows.md`, `design/02-architecture/structure.md`
- 関連Issue / PR: `#142`

## 期待する成果

- 実装: 一覧画面で担当者を選ぶと該当問い合わせのみ表示する
- ドキュメント更新: フロー図または画面仕様に必要なら反映する
- テスト: API の絞り込みテストと UI の表示切替テストを追加する

## 非ゴール

- 今回やらないこと: 複数担当者の OR 検索
- 触らない領域: 通知配信ロジック

## 受け入れ条件

- [ ] 担当者未指定時は既存と同じ一覧を表示する
- [ ] 担当者指定時は対象担当の問い合わせのみ表示する
- [ ] 権限外の問い合わせが見えない
- [ ] API と UI の両方にテストがある
- [ ] 仕様変更がある場合は関連文書を更新する
- [ ] ログ、エラーハンドリング、監視影響を確認する

## 実行上の注意

- 禁止事項: 一覧 API の既存レスポンス形式を壊さない
- 既知のリスク: フィルタ条件追加でクエリ性能が落ちる可能性がある
- レビューで見てほしい点: 権限制御と検索条件の扱い
- ロールバック方針: UI のフィルタ非表示と API パラメータ無効化で戻せる

## 検証

- 実行コマンド: `pnpm test --filter inquiries`, `bundle exec rspec spec/requests/inquiries_spec.rb`
- 確認観点: 既存一覧、担当者別表示、権限別表示
- 未実施なら理由: E2E は別タスクで実施
